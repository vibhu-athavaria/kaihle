# Privacy Gaps: what the code does not yet do

**Status:** DRAFT. Engineering findings from reading the code on 2026-10-11 (task MLH-T19). Not legal advice. Each gap says what the policy draft would need, what the code does today, and a suggested follow-up task. Task ids below are **suggestions** for Vibhu to number; none is created. Nothing here was fixed; this task changes no code, schema or config.

Severity is an engineering judgement of privacy exposure only: **High** (child-written text or credentials exposed or kept indefinitely), **Medium**, **Low**.

## Proposed CONSTITUTION changes (not made here; the CONSTITUTION was not edited)

1. Add a rule: any change to a prompt template, an LLM call site, `TASK_MODEL_MAP`, or a table holding personal data must update `docs/privacy/` in the same pull request.
2. Add the retention schedule to section 4 once decided, with the purge jobs as required tasks.
3. Amend Rule 4 or record an ADR for the sanctioned exceptions, if any, to "all LLM calls go through `router.py`" (currently the seed script).
4. Add `docs/privacy/` to the "Where to find things" table in section 13.
5. Add a short rule on logging: no email addresses or other direct identifiers in log fields (supports G-8).

## Suggested order

1. Decisions (no code): retention periods (G-1/G-4), whether to restrict export (G-10), counsel review of the policy.
2. Quick wins with small PRs: G-9 (credential email), G-8 (log hygiene), G-11 (seed script via router).
3. Core privacy features: G-1 purge job, then G-3 child-facing notice, then G-5 consent/notice record, then G-2 export/erase.
4. G-14 schema reconciliation can run in parallel.
5. T18 slices (G-6), with the T18 flag amendment (G-18) applied first.
