### Task B1: Create Curriculum Service Layer
**File:** `backend/app/services/curriculum_service.py`  
**Agent:** Kramer (backend architecture)  
**Estimated:** 2-3 hours  

**Implementation Requirements:**
- Create `CurriculumService` class with `db: AsyncSession` constructor (follow `UserService` pattern)
- Implement all CRUD operations with proper error handling:

```python
# Curriculum operations
create_curriculum(data: CurriculumCreate) -> Curriculum
update_curriculum(curriculum_id: UUID, data: CurriculumUpdate) -> Curriculum

# Grade operations  
create_grade(data: GradeCreate) -> Grade
update_grade(grade_id: UUID, data: GradeUpdate) -> Grade

# Subject operations
create_subject(data: SubjectCreate) -> Subject
update_subject(subject_id: UUID, data: SubjectUpdate) -> Subject

# CurriculumSubject (link/unlink)
link_subject_to_curriculum(curriculum_id: UUID, data: LinkSubjectRequest) -> CurriculumSubject
unlink_subject_from_curriculum(curriculum_id: UUID, subject_id: UUID) -> None

# Topic operations (two-step: identity + placement)
add_topic_to_curriculum(
    curriculum_id: UUID, grade_id: UUID, subject_id: UUID,
    data: CurriculumTopicCreate
) -> TopicAdminResponse
update_curriculum_topic(ct_id: UUID, data: CurriculumTopicUpdate) -> TopicAdminResponse
delete_curriculum_topic(ct_id: UUID) -> None

# Subtopic operations
create_subtopic(ct_id: UUID, data: SubtopicCreate) -> Subtopic
update_subtopic(subtopic_id: UUID, data: SubtopicUpdate) -> Subtopic
```

**Error Handling:**
- `ValueError` with descriptive messages for business logic violations
- Check unique constraints (name/code) before DB operations
- Validate grade level 1-13, difficulty level 1-5
- Check for duplicate placements in curriculum_topics

**Validation Rules per Spec:**
- `grades.level` must be 1–13 (DB CHECK + service validation)
- `subtopics.difficulty_level` must be 1–5 (DB CHECK + service validation)
- `subtopics.learning_objective` NOT NULL, min 10 chars
- `curricula.name`, `curricula.code` UNIQUE
- `subjects.name`, `subjects.code` UNIQUE
- `grades.level` UNIQUE
- `curriculum_topics` composite UNIQUE (curriculum_id, subject_id, grade_id, topic_id)

**Add to existing curriculum.py (read-only routes already exist):**

```python
# All routes require: require_role(UserRole.KAIHLE_ADMIN)

POST   /curricula → 201 CurriculumAdminResponse
PATCH  /curricula/{curriculum_id} → 200 CurriculumAdminResponse

POST   /grades → 201 GradeAdminResponse  
PATCH  /grades/{grade_id} → 200 GradeAdminResponse

POST   /subjects → 201 SubjectAdminResponse
PATCH  /subjects/{subject_id} → 200 SubjectAdminResponse

POST   /curricula/{curriculum_id}/subjects → 201 CurriculumSubjectResponse
DELETE /curricula/{curriculum_id}/subjects/{subject_id} → 204

POST   /curricula/{curriculum_id}/grades/{grade_id}/subjects/{subject_id}/topics → 201 TopicAdminResponse
PATCH  /curriculum-topics/{ct_id} → 200 TopicAdminResponse
DELETE /curriculum-topics/{ct_id} → 204

POST   /curriculum-topics/{ct_id}/subtopics → 201 SubtopicAdminResponse
PATCH  /subtopics/{subtopic_id} → 200 SubtopicAdminResponse
```

**Error Responses per Spec:**
- 400: "Provide exactly one of topic_id or topic_data"
- 404: Entity not found
- 409: Conflict (duplicate name/code/level/placement)
- 422: Validation error (level out of range, etc.)

**Rule Compliance:**
- Rule 1: All logic in `curriculum_service.py`, routes are thin handlers
- Rule 4: No direct DB queries in routes
- Rule 12: KAIHLE_ADMIN bypass — no school_id filter

## Summary of Changes from Original Spec

Based on user clarifications:

1. **Subtopic Reuse (Major UX change):** AddSubtopicModal now has a 2-step flow: first search existing subtopics for this topic/subject, then either select one (pre-fills fields) or create new.

2. **Drag-and-Drop Reordering:** New task F5b added using @dnd-kit library for topics and subtopics tables.

3. **Color Picker:** Use brand colors from tailwind.config.js first.

4. **Icon Preview:** Dynamic Lucide icon preview in CreateSubjectModal.

5. **Auto Sequence:** Backend calculates sequence_order = max + 1 when null.
