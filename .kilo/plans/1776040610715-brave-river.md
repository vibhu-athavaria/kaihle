# Student App UI/UX Review & Improvement Plan

## Context
Senior UI/UX review of the Kaihle student app (`apps/student`) with focus on student-first thinking, consistency with the design system, and actionable improvements.

---

## Priority 1: Critical Bugs

### 1.1 ClassCard Typo — `frontend/apps/student/src/components/ClassCard.tsx:81`
**Problem:** Two CSS class typos:
- `ffont-sans` → should be `font-sans`
- `mb-` (incomplete) → should be `mb-1`

**Student impact:** Card metadata text renders incorrectly.

### 1.2 Wrong Background Token in OnboardingLayout — `frontend/packages/ui/src/layouts/OnboardingLayout.tsx:18`
**Problem:** Uses `bg-brand-bg` which is `#f5f7f1` (Teacher/School Admin background)
**Should be:** `bg-role-student-bg` which is `#f9fafb`

**Student impact:** Onboarding feels mismatched from student app brand.

### 1.3 MyProgress Hover Background — `frontend/apps/student/src/pages/my-progress/MyProgress.tsx:123-137`
**Problem:** Uses `hover:bg-brand-bg` which is `#f5f7f1` (wrong temperature for student)
**Should be:** `hover:bg-gray-50` or a role-specific surface token

---

## Priority 2: Font Family Inconsistencies

### 2.1 Font Token Naming (Design System vs Implementation)
The design system uses `font-display` and `font-sans`, but several files use literal class names:

| Location | Current | Should Be |
|----------|---------|-----------|
| `AccountSection.tsx:69` | `font-fraunces` | `font-display` |
| `AccountSection.tsx:76-79` | `font-nunito` | `font-sans` |
| `Modal.tsx:84` | `font-fraunces` | `font-display` |
| `LearningProfileSection.tsx:79,95` | `font-nunito` | `font-sans` |
| `LearningProfileSection.tsx` | `bg-green-50`, `border-green-200` | `bg-brand-green-light`, `border-brand-mid` |

**Student impact:** Typography hierarchy breaks; student feels less "app-like"

### 2.2 Border Color Inconsistencies
Multiple files use `border-gray-100/50` instead of role-specific brand tokens:
- `AccountSection.tsx:68` — `border-gray-100` 
- `LearningProfileSection.tsx:53` — `border-gray-100`
- `Settings pages` — mixed `gray-50`, `gray-100`

**Should:** Use `border-role-student-border` (`#e5e7eb`) per design system §5.4

---

## Priority 3: Empty States

### 3.1 Study Plans & Assessments Empty States
**Location:** `StudyPlans.tsx`, `Assessments.tsx`
**Problem:** Use inline placeholder divs instead of `<EmptyState>` component from `@kaihle/ui`

**Student impact:** Inconsistent with rest of app; empty states are a key student UX moment.

---

## Priority 4: Interactive & Hover States

### 4.1 Settings Page Hover
**Location:** `StudentSettings.tsx`
**Problem:** `hover:bg-brand-bg` used in student context
**Should:** `hover:bg-gray-50`

### 4.2 Interest Tags in Onboarding
**Location:** `ProfileQuestionnaire.tsx:107-143, 150-185`
**Problem:** Uses `bg-brand-light` (general green tint) instead of role-specific `bg-[#f0fdf4]`
**Should:** Role-specific student tint `bg-[#f0fdf4]`

### 4.3 Progress Bars in Settings
**Location:** `LearningProfileSection.tsx:82,85`
**Problem:** Uses `bg-gray-100` / `bg-gray-300` instead of brand tokens
**Should:** `bg-brand-border` / `bg-brand-muted`

---

## Priority 5: Design System Violations

### 5.1 Section Labels
**Location:** Multiple dashboard components
**Problem:** Uses `text-brand-body` (`#4a5240`) instead of `text-brand-muted` (`#9ca3af`)
**Per design system §5.4:** Section labels should be `text-brand-muted`

### 5.2 Card Gap Inconsistency
**Location:** `StudentDashboard.tsx:136`
**Problem:** Uses `gap-3` instead of spec's `gap-4`
**Per design system §7:** Card gap should be `gap-4`

### 5.3 Button Touch Target
**Location:** `Button.tsx` small variant
**Problem:** Missing `min-h-[44px]` touch target
**Per design system §9:** All interactive elements must have 44px minimum touch target

---

## Priority 6: Accessibility Improvements

### 6.1 Contrast Issue
**Location:** `MyProgress.tsx:172-180`
**Problem:** `text-brand-amber/80` may not meet WCAG 4.5:1 contrast ratio
**Should:** Use full opacity `text-brand-amber` or `text-brand-amber-dark`

### 6.2 Decorative Emoji
**Location:** `StudentLayout.tsx:260` (greeting emoji 👋)
**Should have:** `aria-hidden="true"` if decorative

---

## What Was Implemented Well ✅

- Mastery color system via `getMasteryStyle()` helper
- Subject dot colors matching §8 spec
- Sidebar dimensions and styling (200px, nav items, active state with green dot)
- Student role palette (`#f9fafb` background, `bg-[#f0fdf4]` active tint)
- ScoreRing component with proper aria-labels
- Progress bar implementation
- Card lift effect on interactive variant
- Focus rings and touch targets elsewhere
- Typography scale (rem-based)
- EmptyState component itself
