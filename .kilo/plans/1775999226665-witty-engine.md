# Plan: Optimize Teacher Students Page API Calls

## Problem Statement

When loading `/teacher/students`, the page makes excessive API calls:
- Multiple calls to `/classes/{classId}/enrollments` (7 calls for 3 classes)
- Multiple calls to `/classes/{classId}/gap-map` (6 calls)
- Learning profile calls for each student

**Current Issue**: The page fetches ALL data (mastery, learning style) upfront, but only needs to display:
- Student name
- Which class they're enrolled in
- A "Detail" button

The detailed data (mastery, learning style) should only be loaded when viewing student detail.

---

## Recommended Approach: New Aggregated API Endpoint

### Design Decision

The student list page should only fetch **basic student info**:
- Student name
- Email
- Enrolled class(es)

**Mastery, learning style, and other detailed data** should be loaded on-demand when:
- User clicks "Detail" button
- Or navigates to student profile page

This aligns with your requirement and is more performant.

### Architecture

**New Endpoint:** `GET /api/v1/teachers/me/students`

**Request:**
```
GET /api/v1/teachers/me/students?school_id={uuid}
```

**Response:**
```json
{
  "students": [
    {
      "id": "uuid",
      "first_name": "John",
      "last_name": "Doe",
      "email": "john@example.com",
      "class_ids": ["class-uuid-1"],
      "class_names": ["Mathematics - Grade 10"]
    }
  ]
}
```

### Backend Implementation

1. **New route**: `app/api/v1/routes/teachers.py`
   - Add `GET /teachers/me/students` endpoint
   
2. **Service**: `ClassService.get_teacher_students(teacher_id, school_id)`
   - Query all active enrollments for teacher's classes
   - Join with User table to get names/emails
   - Return lightweight StudentSummary objects

### Frontend Implementation

1. **New hook**: `useTeacherStudents(schoolId)`
   - Single query returning basic student list
   - Query key: `["teacher", "students", schoolId]`

2. **Update `MyStudentsPage.tsx`**:
   - Remove `useTeacherDashboard` dependency (not needed for student list)
   - Remove `useMyStudents` (fetches too much data)
   - Use new `useTeacherStudents` hook
   - Add "Detail" button per row linking to student profile

3. **Student Detail Page** (`StudentProfilePage.tsx`):
   - Already fetches detailed data (gap-map, learning profile) for that specific student
   - No changes needed - already loads on-demand

## API Endpoint Design

### Endpoint: `GET /api/v1/teachers/me/students`

**Request:**
```
GET /api/v1/teachers/me/students?school_id={uuid}
Authorization: Bearer {token}
```

**Query Parameters:**
| Param | Type | Required | Description |
|-------|------|----------|-------------|
| `school_id` | UUID | Yes | The teacher's school ID |

**Response (200 OK):**
```json
{
  "students": [
    {
      "id": "uuid-string",
      "first_name": "John",
      "last_name": "Doe",
      "email": "john.doe@example.com",
      "class_ids": ["class-uuid-1"],
      "class_names": ["Mathematics - Grade 10"]
    }
  ]
}
```

**Response Schema:**
```python
class TeacherStudentItem(BaseModel):
    id: uuid.UUID
    first_name: str
    last_name: str
    email: str
    class_ids: list[uuid.UUID]
    class_names: list[str]

class TeacherStudentsResponse(BaseModel):
    students: list[TeacherStudentItem]
```

## API Call Comparison

**Before:**
- 3 classes × 1 enrollments = 3 calls
- 3 classes × 2 subjects × 1 gap-map = 6 calls
- N students × 1 learning profile = N calls
- **Total: 9+ calls**

**After:**
- 1 call to `/teachers/me/students`
- **Total: 1 call**

Detail page (when clicked):
- 1 call to `/students/{id}/gap-map` (already exists)
- 1 call to `/onboarding/learning-profile` (already exists)
